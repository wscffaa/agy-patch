# 防御性模式

[English](README.md) | 中文

经验性规则。本目录中的每个模式都是评审中执行的要求，写明规则本身以及它所防止的缺陷。每条规则说明必须成立的内容、评审者据以判断的条件、适用边界与例外审批人，并给出一个正确示例和一个错误示例。修改某类产物前，先阅读对应页面。

## 为什么是这些规则

五个习惯覆盖了下面大部分内容，每个页面都把它们应用到一类产物上：

- **让正确性显式化。** 把它写进结构（具名调用点、显式生命周期、显式条件与类型），而不是事后靠时序来弥补。
- **保持单一事实来源。** 每类数据一条读取路径，每个事实一个归属，每份共享状态一个所有者。
- **通过已注册的接口扩展。** 新能力通过注册接入；已有载体不再接收新逻辑，避免在其内部继续长出分支。
- **让变更面与评审面一致。** 变更只包含其声明的行为变化所需的代码行。迁移移动代码而非重写代码。对性能敏感的变更附带测量数据。
- **要求证据。** 论断必须可证伪、可复算：前后对比测量，或由门禁检查。
